# 配置与调用

以下路径均相对规则包根目录。

## 资产引用

注册表为 `assets/asset-registry.json`，`path_base` 为 `package-root`；每项 `file` 路径不相对注册表文件所在目录。组件声明为 `rules/component-bindings.json`，其中 `registry_ref` 指向上述注册表。

| 组件 | 资产 ID | 版本 |
| --- | --- | --- |
| Logo | `didi.chuxing.logo.horizontal.reverse` | `1.0.0` |
| 识别口号 | `didi.chuxing.slogan.single-line.reverse` | `1.0.0` |
| 主标题 | `didi.font.hyqihei.65s` | `1.0.0` |
| 副标题／详情 | `didi.font.hyqihei.50s` | `1.0.0` |

字体 CSS 为 `assets/brand/font-faces.css`，其中 URL 相对该 CSS 文件；同步脚本核对它与注册表路径、字体 family 和组件 font_ref 一致。

引擎从 `rules/layout-rules.json` 的 typography 读取字体 family。Logo 和口号的 ID 仍是引擎常量，组件声明用于校验，不自动改变这些常量；替换品牌 ID 时需同步修改引擎与检查逻辑。

主视觉来源为 `task_input`，没有固定 asset_ref。传入 `customImage` 地址；接入方也可登记自有主视觉后传入 `mainVisualRef.asset_id` 和 `version`。该资产须为 `image`、`main_visual` 或 `key_visual` 类型。缺图、错误类型、未知 ID 或版本会报错，不回退到已删除的示例图。

二维码不登记为固定品牌资产。链接编码使用 `url` 和 `qrMarkup`；输入为二维码图片时，调用方需提供保留原图的绘制适配，当前引擎未内置二维码图片字段。

## 检查与同步

```sh
node scripts/sync.mjs --check
node scripts/validate.mjs
node scripts/sync.mjs
```

`--check` 只检查资产路径、字节数、SHA-256、版本引用和字体 CSS。默认同步会创建 `runtime/`，生成 `asset-registry.js` 与 `layout-rules.js`，不依赖 `examples/` 或 manifest。

`validate.mjs` 在 Node 中用估算字宽检查资产引用和基本布局，默认只输出结果，加 `--report` 才写报告。它不执行真实浏览器导出，也不引用已删除的浏览器验证记录。

需要文件哈希清单时，主动运行 `node scripts/update-manifest.mjs` 创建或更新 `manifest.json`；普通同步、校验、出图均不依赖它。

## 浏览器调用

同步后，通过本地 HTTP 服务依次加载字体 CSS、`runtime/asset-registry.js`、`runtime/layout-rules.js`、`engine/didi-split-layout.js`。需要链接二维码时再加载 `engine/qr.js`、`engine/qr-markup.js`。

`preview.html` 提供主视觉文件选择，默认文字和尺寸保存在页面中，不再加载 `examples/input.js`。任务调用方应传入自己的实际数据，例如：

```js
await DidiLayout.ready;
const data = {
  title: '好时光  轻松抵达',
  subtitle: '滴滴打车福利  助力每次出发',
  customImage: 'task-assets/main-visual.png', // 接入方需提供这个实际文件。
  date: '', location: '', url: '',
  splitPreset: 'M', brandPillar: 'horizontal'
};
const target = {label: '竖版', w: 800, h: 1600, unit: 'mm'};
const layout = DidiLayout.plan(data, target);
if (!layout.valid) throw new Error(JSON.stringify(layout.issues));
const svg = DidiLayout.render(data, target, {qrMarkup});
const pngBytes = await DidiLayout.exportPng(data, target, qrMarkup);
// 直接保存 pngBytes，避免再次经 Canvas 编码丢失密度元数据。
```

图片地址和注册表路径按页面所在的规则包根目录解析；跨目录接入应保持基准或提供可访问地址。真实排版与导出需要浏览器 Canvas 和正确加载的字体。

## 输出要求

PNG、72 dpi。px 输入为正整数并保留原宽高；mm 按 `mm ÷ 25.4 × 72` 四舍五入，至少为 1 像素。PNG `pHYs` 横纵各为 2835 像素／米，等效约 72.009 dpi。

字体未加载或布局失败时禁止导出。当前保留 DEMO 水印，只作试排，不提供出血、CMYK 或印前 PDF。
