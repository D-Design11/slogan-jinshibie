# 已确认要求与接入事项

## 本次用户已确认

| 事项 | 确认内容 |
| --- | --- |
| 城市流程 | 确认需求 → 设计生成 → 自动审核 → 查看结果 |
| 网区流程 | 上传主视觉 → 选择版式 → 模版生成 → 预览确认 → 发布资产 |
| 模版推荐 | 网站推荐同网区、同项目下，已发布且有效的最新发布版本 |
| 城市编辑内容 | 仅主标题、副标题、二维码 |
| 发布主体 | 网区制作者预览确认后直接发布；不新增其他审批人 |
| 二维码输入 | 链接生成和上传已有二维码图片，两种都支持 |
| 物料输入形式 | 按类型分组；多选预设；每组可自定义尺寸；可新增物料类型 |
| 物料尺寸单位 | 所有物料统一 mm，包括大屏 |
| 全局必填 | 合并后的主标题必填，不能是空白；副标题与二维码不新增全局必填 |
| 独立审核 | 新增独立 didi-design-audit Skill，两套生成流程调用 |
| 水印 | 不添加系统水印，预览和正式下载一致 |
| 规则分工 | 推荐等业务规则由网站维护；Skill 描述接收结果后如何执行 |

发布、推荐、权限与保存均是网站职责；这些已确认要求尚不代表网站接入已完成。

## 保留与更新的生成能力

- 规则版本 0.3.3，状态 draft；覆盖口号仅作品牌识别的 S/M/L/XL。
- 原始 65S/50S 字体，固定字号，超容量提示，不自动缩字；图片不压暗、不加黑色蒙层。
- PNG 72 dpi，输入 mm 换算像素；引擎已去除水印并增加主标题必填检查。
- 现有 `preview.html` 的默认数据是示例，不能当真实需求或网站表单。

## 不预先假定的扩展

本次已确认项不再重复询问。独立审核先执行已有且有证据的输入、排版和导出检查；视觉可观察问题按实际预览判断。文案事实、链接目标、二维码解码、图片制作质量阈值等需要明确来源或能力，不因拆出 Skill 就宣称全部实现。

网站接口、实际字段映射和存储位置在开发接入时提供，无需业务用户现在决定技术细节。新的业务审核标准可以后续增补到独立审核 Skill，无需改写生成流程。

## 现有接入缺口

| 接入项 | 实际情况与后续工作 |
| --- | --- |
| 项目模版读写、推荐、发布、权限与任务记录 | 原包无后端；需接网站真实接口 |
| 独立审核调度与报告落库 | 已提供 didi-design-audit 入口和报告协议，仍需网站或宿主实际调用 |
| 业务请求转换为引擎参数、逐规格结果返回 | 本次已定义约定，尚需适配层实现 |
| 二维码图片模式 | 原引擎无图片入口；需要同时适配布局占位、预览和 PNG 导出 |
| 二维码编码失败的明确状态 | 原 qrMarkup 会显示占位提示；需要把真实编码状态传给审核 |
| 自由活动说明 details | 原组件声明存在，但引擎只绘制日期和地点；不能静默吞掉其他说明 |
| 真实浏览器验证 | Node 校验是估算度量；接入后需对实际输入做字体、二维码和 PNG 导出验证 |
